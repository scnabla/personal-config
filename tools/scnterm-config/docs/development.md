# 开发说明

## 项目分工

| 文件 | 职责 |
| --- | --- |
| `scnterm_config/lua_document.py` | Lua 静态解析、字段定位、动态代码识别、类型检查和局部替换 |
| `scnterm_config/storage.py` | 配置会话、差异、外部修改检测、备份、文件替换及恢复 |
| `scnterm_config/validation.py` | 调用独立正则检查器，不拼接 Shell 命令 |
| `scnterm_config/app.py` | Windows 独立窗口、串口表单、只读预览、保存和恢复操作 |
| `validator/` | 独立 Rust 正则语法检查程序 |
| `tests/` | 文件保护、实际保存与恢复、Lua 示例处理测试 |
| `scripts/build-windows.ps1` | 项目虚拟环境、测试与 Windows 打包 |

本工具位于 `personal-config/tools/scnterm-config/`，依赖、测试与构建产物均保存在该目录内，不引用 ScnTerm 内部模块。终端版本更新不会要求重新链接本程序。

## Lua 处理

解析器只生成语法树并读取节点位置，不执行配置。已有值按字节区间替换，新字段或列表项在对应表内插入，未修改区域保持原字节。保存前重新解析候选文本，检查原来可识别的章节仍然存在，并核对解析结果与待保存值一致。

每个列表项使用原文位置关联原始记录，避免修改同名连接时误选其他条目。新增条目没有原位置；删除原条目时仅移除对应字段及相邻分隔符，周围注释保留。含动态表达式的条目不允许整体删除。未知字段保留，受支持字段中无法解读的表达式只读。

条件语句保持原样，编辑器显示声明中的值，不将其视为执行 Lua 后的实际结果。多个无法明确对应的赋值按只读处理。缺失章节只在明确的 `M.apply(config)` 函数结束前插入，不改主文件加载路径。

## 保存流程

1. 将表单更改应用到内存模型。
2. 校验类型、范围、颜色、关键词数量和正则语法，生成候选 Lua。
3. 显示候选文件与原文件的差异。
4. 确认后重新生成候选内容，核对与预览一致，并检查磁盘文件未被外部修改。
5. 写入独立备份与对应文件信息。
6. 在目标目录完整写入临时文件，刷新文件内容，再次检查原文件并替换。
7. 重新读取保存结果，重建原文位置和界面状态。

备份记录保存原文件路径及修改前后内容摘要，用于核对恢复对象。恢复前检查备份未被更改且当前内容仍对应该次保存，不能将任意文件作为备份覆盖配置。

## 验证范围

自动测试覆盖无修改时字节与修改时间不变、中文及 BOM/CRLF 保留、单值替换、列表增删、正则反斜杠、注释、动态字段、重复名称、错误范围、外部修改、写入失败、备份恢复及其他配置不变。43 项文件与配置测试在 Linux 和 Windows 通过；Windows 独立桌面完成了连接增删改、日志字段、关键词与正则、确认保存、备份恢复、错误输入和外部修改拦截验证。测试使用配置副本，主配置、SSH 与快捷键文件的字节内容保持不变。

## 构建与发布

`personal-config` 的 `main` 分支中，`tools/scnterm-config/` 下源码、依赖、示例或 `.github/workflows/scnterm-config.yml` 发生变化时，GitHub Actions 执行 Windows 构建。仅修改该工具的 Markdown、`docs/` 或仓库其他目录不会触发构建，也可手动运行工作流。

构建依次执行自动测试、PyInstaller 打包、窗口操作测试和成品启动检查，全部成功后更新单个 `scnterm-config` Release。ZIP 中包含完整运行目录、示例、许可证和 `build-info.json`；该文件记录源码提交、构建地址、Python 版本及包内文件的 SHA256。

程序不需要用户另行安装 Python 或 Rust。开发依赖使用项目虚拟环境；Rust 校验器单独编译，没有终端项目依赖。

本地 Windows 成品已完成启动、打包后正则检查器调用和正常关闭验证。界面验证在独立测试桌面执行，没有切换用户桌面或使用全局键盘鼠标输入。

外部文件语法错误导致重新读取失败时，原会话状态保持不变，后续保存仍会拒绝覆盖外部版本。

完整配置检查使用 ScnTerm 外部命令验证公开示例及编辑结果，包含省略连接参数、日志默认值和高亮设置的情况。该验证仅用于开发测试，编辑器自身不执行 Lua。
